### 执行动作

创建 `docs/development-process.md`：

```markdown
# 开发流程规范

## 分支管理
- main：稳定分支，不允许直接提交
- develop：开发主分支
- feature/xxx：功能分支
- fix/xxx：修复分支

## 提交规范
- 格式：类型: 简述
- 类型：feat / fix / docs / chore / test / refactor
- 示例：feat: 添加数据清洗流水线

## 代码审查
- 所有合并必须通过 PR
- 审查人：至少一人，核心模块需总工程师审查
- 审查清单：功能正确性、安全、性能、代码规范、测试覆盖

## 测试要求
- 单元测试覆盖率 ≥80%
- 核心模块必须有集成测试
- CI 自动运行测试

## 文档要求
- 模块设计文档与代码同仓
- API 变更同步更新文档
```

### 产出物

- `docs/development-process.md`

### 验收标准

- 团队全体成员确认遵守
- 后续开发中实际执行
