> 日期：2026-08-29

## 1. 本轮变更

### 核心：可复用资产注册表（非壳）

新增 `assets/` 模块（`assets/archive.py` 注册表持久化 + `assets/service.py` 注册/检索/建议/接入）：

1. **注册表落盘 `tmp/web/assets/registry.json`**：条目 schema 含 `asset_id`(uuid8)、`kind`（mapping_config|eval_set|kb_chunks|cleaning_rules|quality_report|diagnosis_plan|doc_package）、`title`、`summary`、`tags`、`origin{run_id,module,case_id}`、`project_id`、`customer`、`payload_url`（复用 /artifacts 或 /api/v1 路径，**不复制 payload**）、`payload_path`（本机绝对路径，adopt 时据此读/复制）、`meta`（kind 相关，如 mapping 的 source/target 字段、eval_set 样本数）、`created_at`。
2. **注册函数**：`register_asset(...)` 按 `(kind, run_id)` **幂等去重**（重复注册返回既有条目）；`list_assets(kind, limit)`、`search_assets(q, kinds, tags, customer, limit)`、`get_asset(asset_id)`。
3. **规则评分建议 `suggest(query, kinds, customer, top_k)`**：确定性、可测、离线。候选池用 kinds 硬过滤；评分 = 查询分词在 title/summary/tags 的关键词命中（+2/词，整串命中 title 再 +2）+ 标签命中（+2/标签）+ 同客户（+3）+ 同类资产（+1，叠加在真实信号上）+ 时间衰减（`1/(1+年龄天/60)`）。**仅关键词/标签/同客户信号之一成立才出现**（避免纯类型匹配灌水）。返回 `[{asset, score, reason}]`，reason 如「关键词命中1处 · 同客户 · 同类资产」。

### 注册挂接（真实，三个沉淀入口自动入库）

1. **mapping 导出**：`mapping/service.py::export_mapping` 成功后调用 `register_from_mapping(run_id)` 注册 kind=mapping_config（meta 含 source_fields/target_fields/mapping_count/adapter 路径；payload_url 指向 `adapter/mapping_config.json`；幂等）。返回结果带 `asset`。
2. **dataprep 沉淀**：`dataprep/service.py::_deposit_one` 沉淀后调用 `register_from_dataprep(...)` 注册 4 类数据资产（引用 cases 的 payload_url，不重复落 payload）。
3. **诊断定稿**：`core/api.py::diagnosis_finalize` 生成交付物后调用 `register_from_diagnosis(...)` 注册 kind=diagnosis_plan（幂等；失败不阻断定稿）。

### 自动带出（真实，非写死）

三个创建入口响应**新增 `related_assets` 字段**（不改旧字段、不破坏旧契约）：

- `POST /api/v1/mapping/create` → 按任务名 + 源/目标字段名 suggest（kind=mapping_config）。
- `POST /api/v1/dataprep/create` → 按任务名 + 文件名 suggest（kind∈cleaning_rules/eval_set/kb_chunks/quality_report）。
- `POST /api/v1/diagnosis/start` → **保留现有 `related_cases`**，新增 `related_assets`（含 diagnosis_plan 等）。

通用端点：`GET /assets/list`、`GET /assets/search?q=&kinds=&tags=&customer=`、`GET /assets/suggest`、`GET /assets/{asset_id}`、`POST /assets/{asset_id}/adopt`。

### 一键接入（旗舰：导入历史映射）

`POST /assets/{asset_id}/adopt`（body `{project_id?, customer?, target_run_id?}`）按 kind 分发：

- **mapping_config（旗舰）**：读 asset payload 的历史 source/target 字段 + 映射 → `mapping.service.create_mapping` **预填字段与映射** 建新 run（状态 draft，可继续导入样例/校验/修正），挂项目档案（`asset_reuse` 事件），返回 `{run_id, url, mappings}`。`create_mapping` 新增可选 `prefill_mappings` 参数（提供时跳过 LLM 初判，旧调用不传则行为不变）。
- **eval_set / kb_chunks / cleaning_rules / quality_report**：复制 payload 到目标 dataprep run 的 products（`reused_<kind>.json`，供继续用）；未给 target_run_id 则仅登记为项目资产引用。挂项目 `asset_reuse` 事件。
- **diagnosis_plan / doc_package**：交付物类资产（无 JSON payload 可复制）→ 登记为项目资产引用 + 事件（payload 经 payload_url 下载，不造假）。

### 前端（零构建，⑪ 资产库 tab）

`web/index.html` 加 ⑪ tab-assets「资产库」；`web/app.js`：
- 资产库视图：搜索/筛选（kind 下拉 + tags + q + 客户）+ 列表（标题/类型标签/客户/时间/下载链接）+ 详情（kvTable）+ 「一键接入」按钮（mapping_config → 跳转 ⑨ 工作区续做；数据资产 → 可填目标 run 或仅登记引用）。
- ③ 数据作战流 create 表单下方渲染 `related_assets`（一键接入 = 复制到当前 run 的 products 继续用）。
- ⑨ 字段映射 create 表单下方渲染 `related_assets`（一键接入 = 导入历史映射预填）。
- ① 诊断：相关案例保持，新增相关资产展示（可一键接入/下载）。

### 测试

新增 `tests/test_assets.py`（10 用例，**非教学场景**：制造业设备字段映射 / 零售库存 / 物流订单）：
1. 注册表真实：register/list/get/search（按 kind/tags/customer/关键词）+ (kind, run_id) 幂等去重 + 未知 kind 拒绝。
2. suggest 规则评分：关键词命中 + 同客户 + 同类资产 + reason；无信号查询返回空。
3. mapping export 自动注册 kind=mapping_config 资产（meta 字段 + payload 可读 + 重复 export 幂等）。
4. dataprep deposit 自动注册 4 类资产（eval_set/kb_chunks/cleaning_rules/quality_report）。
5. mapping/dataprep/diagnosis 创建接口返回 `related_assets`（旧字段不破坏）。
6. adopt mapping_config 建新 run 预填历史映射（draft）+ 挂 asset_reuse 事件。
7. adopt 数据资产写目标 run products + 挂事件；未给 target_run_id 仅登记引用。
8. 通用检索端点（list/search/get + 404）。

LLM 全部打桩；ChromaDB 用确定性 fake 嵌入；注册表隔离到临时目录（不污染真实数据）。真实链路（真实数据 + 真实 ChromaDB 语义去重/索引 + 真实 registry）单独冒烟验证。

## 3. 运行 / 验证方式

```bash
source venv/bin/activate
python -m pytest tests/          # 回归：123 passed（原 113 + 新增 10）

python -m core.main              # 启动服务器，端口 8100
# 浏览器打开 http://localhost:8100 → ⑪ 资产库 查看/检索/一键接入
# → ⑨ 字段映射 导出一次 → ⑪ 资产库出现「字段映射配置」资产 → 新建映射任务时下方自动带出 → 一键接入预填
# → ③ 数据作战流 跑完沉淀 → ⑪ 资产库出现 4 类数据资产 → 新建数据任务时自动带出 → 一键接入复制到当前 run
```

跑真实链路（真实数据 + 真实 ChromaDB 语义去重/索引 + 真实 registry）：
1. ⑨ 字段映射 → 新建（制造业设备字段映射，源/目标字段）→ 保存映射 → 导出适配器 → ⑪ 资产库出现「字段映射配置 · 制造业设备字段映射」（payload_url = `/artifacts/mapping/<run_id>/adapter/mapping_config.json`）。
2. ⑨ 新建另一个映射任务 → 下方「相关可复用资产」自动带出该映射配置 → 点「一键接入」→ 新 run 预填历史映射（4 条，状态 draft）→ 跳转 ⑨ 工作区续做。
3. ③ 数据作战流 → 上传制造业传感器 CSV → 跑评测集 + 知识库 → 点「沉淀可复用资产」→ ⑪ 资产库出现 评测集/知识库分块/清洗规则/质量报告。
4. ③ 新建另一个数据任务（同客户）→ 下方自动带出相关数据资产 → 点「一键接入」→ payload 写入该 run 的 products（`reused_*.json`），项目档案出现 `asset_reuse` 事件。
