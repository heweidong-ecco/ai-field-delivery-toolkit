# 数据准备 · 数据作战流 · 更新日志 v3.0

> 日期：2026-08-29
> 版本号：v3.0（项目级数据准备流水线：以项目为单位、可断点续接、产物沉淀复用）
> 关联：基于既有 data_prep/annotation/kb 能力做「数据作战流」编排；诊断/案例/项目等既有模块不动。
> 本轮主题：把数据准备从「单次跑管道」升级为「以项目为单位、可断点续接、产物沉淀复用」的作战流——解决现场 30-40% 时间被数据准备吃掉、当前 data_prep/annotation/kb 彼此脱节、不可续接、不沉淀复用的问题。

---

## 1. 本轮变更

### 核心：新增 `dataprep/` 数据作战流模块

**现状问题**：数据准备占 FDE 现场 30-40% 时间，是最大时间块。当前 `data_prep/pipeline.py`（一次性跑完 清洗+评测集）、`annotation/service.py`（独立标注任务）、`kb/service.py`（独立分块质检）彼此脱节，不可续接、不沉淀复用。现场做完一次数据准备，下次从零再来。

**本轮做成「数据作战流」**：以 run_id 为任务标识、以项目为单位、六步流水线，每步可单独执行、可续接（刷新/重连不丢），产物真实落盘进档案，且可沉淀为带标签的可复用资产（`search_cases` 可检索）。

六步流水线（`dataprep/service.py`）：
1. **导入数据**（`import_data`）：上传 csv/json 真实数据；检测源类型、记录行数；产物 `raw_data.json` + `source_info.json`。
2. **清洗**（`clean_step`）：复用 `data_prep.cleaning`——字符级去重（deduplicate）+ 语义去重（semantic_deduplicate，阈值 0.85）+ 异常过滤（filter_anomalies）+ 归一化（normalize）+ PII 脱敏（mask_pii）；产物 `cleaned_data.json` + `cleaning_stats.json`。
3. **质量报告**（`quality_step`）：复用 `DataQualityEvaluator`；产物 `quality_report.json`。
4. **标注**（`annotate_step`）：复用 `annotation.service`——建标注任务 + 双人打标签（确定性规则，纯规则不用 LLM）+ 看一致性；产物 `annotation_eval_set.json`（标注一致样本评测集）。
5. **评测集**（`eval_set_step`）：复用 `EvalSetBuilder`（纯规则）；产物 `eval_set.json`。
6. **知识库**（`kb_step`）：复用 `kb.service` 分块 + 质检；产物 `chunks.json`（含质检报告）。

每步执行后 `mark_step` 更新 status/steps/products，**刷新不丢**；`get_state(run_id)` 返回可恢复状态（断点续接入口）、`continue_step(run_id, step)` 执行指定步或 run_next 顺序推进。

### 任务挂项目档案

任务创建时若传 `project_id` 则 `add_event` 到项目；否则按客户名自动建/复用项目（参考 `core/api.py` 的 `_ensure_project`）。事件类型 `dataprep`（建任务）/ `dataprep_asset`（沉淀资产），`ref=run_id`，项目时间线可见。

### 复用资产沉淀

清洗后数据 / 评测集 / 知识库分块 / 质量报告 → 带标签沉淀为可复用资产（`cases/archive`），`search_cases` 可检索：
- **评测集**（`asset_type=eval_set`）：`EvalSetBuilder` 产物，标签 `["数据准备","评测集","可复用资产"]`
- **知识库分块**（`asset_type=kb_chunks`）：分块 + 质检报告，标签 `["数据准备","知识库分块","可复用资产"]`
- **清洗规则说明**（`asset_type=cleaning_rules`）：五条清洗规则 + 源信息 + 清洗统计，标签 `["数据准备","清洗规则","可复用资产"]`
- **质量报告**（`asset_type=quality_report`）：重复率/PII/覆盖度，标签 `["数据准备","质量报告","可复用资产"]`

每个资产 `asset.json` 真实落盘（`/artifacts/cases/<case_id>/asset.json` 可下载），元数据进 `archive.json` 供检索。

### API

- `POST /api/v1/dataprep/create` — `{name, project_id?, customer?, file(UploadFile)}` → 建任务 + 导入数据 + 自动跑 清洗/质量（前三步），返回 run_id/status（可恢复状态）。
- `GET /api/v1/dataprep/runs` — 任务列表（名字/状态/进度/可恢复状态）。
- `GET /api/v1/dataprep/{run_id}` — 状态 + 各步产物（断点续接入口）。
- `POST /api/v1/dataprep/{run_id}/step` — `{step: "annotate"|"eval_set"|"knowledge_base"|…}` 或 `{run_next: true}` 顺序推进。
- `POST /api/v1/dataprep/{run_id}/rename` — 人工命名。
- `POST /api/v1/dataprep/{run_id}/deposit` — 沉淀可复用资产。
- 产物下载复用现有 `/artifacts`（返回 `products[*].url`）。

### 前端（零构建）

③ 数据准备 tab 顶部新增「数据作战流」面板：
- 新建任务：任务名 + 上传 csv/json + 客户（自动建/复用项目）+ 可选项目 ID → 上传并自动跑前三步。
- 任务列表：名字 / 数据源 / 状态 / 进度 / 查看继续 / 重命名（复用①需求诊断「历史诊断/继续」交互风格）。
- 点开任务：六步状态表 + 每步产物下载链接 + 「继续」按钮（单步 + 顺序推进下一步）+ 「沉淀可复用资产」入口 + 已沉淀资产列表。

## 3. 运行 / 验证方式

```bash
source venv/bin/activate
python -m pytest tests/          # 回归：103 passed（原 99 + 新增 4）

python -m core.main              # 启动服务器，端口 8100
# 浏览器打开 http://localhost:8100  → ③ 数据准备
```

跑真实数据（**非教学场景：制造业传感器 CSV**）：
1. ③ 数据准备 → 「数据作战流」→ 新建任务：任务名「制造业传感器预测性维护」+ 上传 `sensor_data.csv`（真实传感器读数）+ 客户「某汽车制造厂」→ 上传并自动跑前三步（导入/清洗/质量）。
2. 点开任务看到 6 步状态表：前三步 done，产物（raw_data / cleaned_data / quality_report / cleaning_stats / source_info）可下载。
3. 点「④ 标注」→「⑤ 评测集」→「⑥ 知识库」逐项继续（或「顺序推进下一步」）。
4. 全部完成（进度 6/6）→「沉淀可复用资产」→ 在「案例检索」搜「评测集 / 知识库分块 / 清洗规则」可搜到资产并下载 `asset.json`。
5. 刷新页面 →「列出数据作战流任务」→ 点「查看/继续」→ 状态完整恢复（断点续接不丢）。

## 4. 自测结果

- `pytest tests/`：**103 passed**（v2.2 基线 99，新增 4 个数据作战流用例；旧用例零改动全部保持绿）。
- **真实数据全链路（制造业传感器 CSV，真实 ChromaDB 默认嵌入，本机缓存模型）**：上传 46 行（40 温度 + 4 重复 + 1 PII + 1 短）→ 导入 46 → 字符去重 43 → 语义去重保留 3 → 质量 → 标注（双人一致）→ 评测集 → 知识库分块 → `status=completed`，8 个产物文件全部真实落盘且 `/artifacts` 可下载。
- **断点续接**：`start_task`（前三步）→ `get_state`（进度 3/6，刷新不丢）→ `continue_step` run_next 依次推进到 6/6 → 再 `get_state` 仍完整恢复。
- **资产沉淀可检索**：`deposit` 沉淀 4 项（eval_set / kb_chunks / cleaning_rules / quality_report），`search_cases(query="评测集")` 与 `search_cases(tags=["知识库分块"])` 均能检索到对应资产；`asset.json` 可下载。
- **任务挂项目档案**：按客户自动建项目，`dataprep` + `dataprep_asset` 事件出现在项目时间线（`ref=run_id`）。
- **前端零构建**：纯 HTML/JS/CSS，无 node 依赖（`node --check web/app.js` 通过）。
