# 原型 + 知识库打通（RAG 链路）· 更新日志 v5.0

> 日期：2026-08-29
> 版本号：v5.0（从「QA 模板只调 DeepSeek 空答、没接客户数据/知识库」打通到「分块 → 向量化(ChromaDB) → 检索 → 问答带引用」）
> 关联：基于既有 kb.service 分块 / 数据作战流 v3.0 / 原型组装器 QA 模板做链路打通；诊断 v2.2 / 数据作战流 v3.0 / 集成工作台 v4.0 / 前端 10 标签均不动。
> 本轮主题：原型阶段（1-2 周）要「用真实数据验证核心假设」。此前 QA 模板只调 DeepSeek 空答，没接客户数据/知识库——验证不了「基于客户文档的 RAG 问答」这个最主流假设。数据作战流已能产出知识库分块（kb.service chunks），本轮把「分块 → 向量化 → 检索 → 问答（带引用）」做成真链路。

## 1. 本轮变更

### 核心：真实 RAG 链路（非壳）

新增 `retrieval/` 模块（`retrieval/service.py`），三件事都是真的：

1. **索引进 ChromaDB（真实向量化）**：`index_knowledge(kb_run_id, chunks)` 用 ChromaDB PersistentClient + 默认嵌入模型（本机已缓存 ONNX MiniLM，离线可用）把分块写入 collection `kb_<run_id>`，HNSW 向量索引，cosine 空间；幂等重建（先清旧再写）。过短分块（<20 字，与 kb.quality_check 的 too_short 阈值一致）会被过滤——否则 4 字块（如「防尘罩。」）嵌入向量高度泛化会让检索排序失真（实测排到最前）。索引档案写 `tmp/web/retrieval/<kb_run_id>/archive.json`（collection 名、块数、索引时间）。
   - **关键修复**：macOS 上 onnxruntime 的 CoreMLExecutionProvider 对**批量**输入偶发崩溃（单条正常），强制 `preferred_providers=["CPUExecutionProvider"]` 稳定。
2. **检索（真实 ChromaDB 最近邻）**：`retrieve(kb_run_id, query, top_k)` 用 collection 的嵌入函数嵌入 query → 向量查询 top_k → 返回 `[{chunk, score(余弦相似度), distance, source}]`；未索引抛 FileNotFoundError（API 层 404）。
3. **RAG 问答（真调 LLM + 引用）**：`rag_answer(kb_run_id, query, llm_call=None)` 检索 top_k → 组装 prompt（系统：「基于以下知识库内容回答，不确定就说不知道，并标注引用分块」+ 编号分块 `[1]…[k]`）→ 调 `core/llm.chat`（真实 DeepSeek）→ 返回 `{answer, sources:[{chunk 前100字, score}]}`。

### 数据作战流衔接（自动索引 → RAG 就绪）

`dataprep/service.py` 的 `kb_step`（knowledge_base 步骤）分块 + 质检后**自动调用 `retrieval.index_knowledge`**，产物与步骤记录 `indexed: true` + `collection`（如 `kb_<run_id>`）；索引进失败不阻断流程（降级为 `indexed: false`，保证数据作战流不受影响）。前端③数据准备 tab 知识库步骤显示「已索引 · RAG 就绪」。新增 `load_kb_chunks(run_id)` 供 API 重建索引时从产物读取。

### 原型 QA 接知识库

`prototype_assembler/templates/qa_agent.py`：`create_qa_agent(kb_run_id=None, top_k=5)`。带 kb_run_id 时，运行时（`_qa_llm_call`）先 `retrieval.retrieve` 检索相关分块拼进上下文再答（系统提示要求标注引用），并把引用分块缓存到 `agent.last_sources` 供 API 返回；不带 kb_run_id 保持普通问答原逻辑。`assembler.create/run` 支持 kwargs 透传。

### API

- `POST /api/v1/retrieval/index` — `{kb_run_id, chunks?}`；缺省 chunks 自动从数据作战流产物读取 → `{collection, chunk_count, kb_run_id}`。
- `POST /api/v1/retrieval/query` — `{kb_run_id, query, top_k}` → `{answer, sources}`。
- `GET /api/v1/retrieval/indexed` — 列出已索引知识库（前端「选择知识库」下拉数据源）。
- `POST /api/v1/prototype/run` — 增加可选 `kb_run_id`；有则走 RAG，返回 `rag:true + sources`；无则保持普通问答。

### 前端（零构建）

④ 原型 tab：新增「知识库（可选，走 RAG 检索问答）」下拉（列出已索引 kb_run_id · 块数 · 时间）+ 手动索引面板 + 结果区展示回答 + 引用分块（相似度 + 前 100 字）。③ 数据作战流知识库步骤显示「已索引 · RAG 就绪」。纯 HTML/JS/CSS，无 node 依赖。

### 测试

新增 `tests/test_retrieval.py`（6 用例，**非教学场景**：设备运维手册/故障处理指南）：
1. `test_retrieval_manufacturing_manual_full_chain`：分块 → 索引（collection/块数/档案/列表）→ 检索（「E001 故障」命中含 E001 分块、「传感器」命中 E002 分块）→ rag_answer（LLM 打桩返回含引用，sources 截断前 100 字）。
2. `test_retrieval_rag_answer_sources_and_honest_unknown`：sources 截断 + 无相关知识时打桩 LLM 诚实返回「未找到」。
3. `test_retrieval_retrieve_unindexed_raises`：未索引检索报 FileNotFoundError。
4. `test_retrieval_dataprep_kb_product_indexable`：数据作战流传感器 CSV → 前三步 → 顺序推进到 knowledge_base → 自动索引（`indexed=True`、`collection=kb_<run_id>`）→ 检索可用（闭环）。
5. `test_retrieval_api_index_query`：API 索引 → 已索引列表 → 查询（LLM 打桩）。
6. `test_prototype_run_with_kb_rag`：原型 run 带 kb_run_id → `rag:true` + sources（LLM 打桩）。

检索用确定性 fake 嵌入（字符二元组袋，1024 维），RAG 问答 LLM 全打桩；真实链路（真实 MiniLM + 真实 DeepSeek）冒烟单独验证。

## 3. 运行 / 验证方式

```bash
source venv/bin/activate
python -m pytest tests/          # 回归：113 passed（原 107 + 新增 6）

python -m core.main              # 启动服务器，端口 8100
# 浏览器打开 http://localhost:8100 → ③ 数据准备 → 数据作战流跑 knowledge_base → 显示「已索引 · RAG 就绪」
# → ④ 原型 tab → 选 knowledge_qa + 该知识库 + 问题 → 运行 → 回答带引用 + 引用分块
```

跑真实数据（**非教学场景：设备运维手册，真实 DeepSeek**）：
1. ④ 原型 tab → 手动索引：kb_run_id 填 `ops_manual_0629`，分块粘贴设备运维手册（E001/E002/E003 故障代码 + 日常维护 + 网络安全）→ 索引进 ChromaDB。

## 4. 自测结果

- `pytest tests/`：**113 passed**（v5.0 基线 107，新增 6 个 retrieval 用例；旧用例零改动全部保持绿）。
- **真实链路冒烟（真实 MiniLM 嵌入 + 真实 DeepSeek，非教学场景设备运维手册）**：
  - `index_knowledge('ops_smoke_0629', chunks)` → collection `kb_ops_smoke_0629`，3 块（真实向量化写入 ChromaDB）。
  - `retrieve('ops_smoke_0629', '设备出现E001故障如何排查？', top_k=3)` → top1 score 0.6259 且 chunk 含 **E001**（E002 块 0.5608、维护块 0.4793）——检索命中相关块。

  - 无关问题「这台设备怎么连蓝牙？」→ 回答「知识库中未找到相关信息」——**无相关知识时诚实说不知道**。

- **API**：`POST /retrieval/index` / `POST /retrieval/query` / `GET /retrieval/indexed` 注册且可用（TestClient 验证）；`POST /prototype/run` 带 kb_run_id 返回 `rag:true + sources`。
