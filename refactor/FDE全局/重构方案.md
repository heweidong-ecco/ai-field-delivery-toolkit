## 一、北极星原则(Q1)

**工具包的目的不是省时间,是把事做好(质量+口碑)。** 省时间是质量保证前提下、靠「系统沉淀能力 + Agent 记忆系统」换来的副产品。

系统必须:
1. **可操作**:保质量、能迭代、自身进化、加速 FDE 过程
2. **沉淀**:保存案例过程/总结/Demo/PDF/真实项目,可打印或发客户看
3. **说服力**:用真实落地项目建立强说服力

## 四、接线决策

1. **第一步**:诊断定稿(v 版报告 + 过程)→ **案例/交付物层**(可打印/发客户)→ 案例结构化存档(带标签)
2. **第二步**:诊断结论(高风险/不推荐维度 + 置信度)→ **裁剪器**(部分自动,人工可改)
3. **第三步(二期)**:案例检索 → 下次交付自动带出相关案例/模板(Agent 记忆)

---

## 五、技术底座

- `core/llm.py` 统一客户端:诊断/原型/字段映射/交付文档共用;**计费打点自动喂 monitor**
- **模块 manifest(自描述)**:每模块/API 自带 名称/简介/输入/输出/使用场景/规范/示例 → 自动聚合生成操作台说明 + API 文档;**简介/规范文本人工维护**,结构自动
- **插件化/懒加载**:模块 = 目录即插件;模板沉淀各目录;操作台按需挂载
- **档案机制复用**:run_id JSON 档案(诊断模式)推广到映射工作台/项目过程
- **对抗评审模式**:只在"发给客户/影响决策"的产出套(诊断/裁剪/交付物)

## 六、工作流(SOP)设计

**标准骨架(推荐默认流程)+ 自适应分支**:
```
① 需求诊断(对抗评审,人工确认)
   └─ 产出 → 案例/交付物层(可打印报告)
② 数据准备(含标注/评测集管理)
   ├─ 硬门禁:数据未达标不进原型
   └─ 知识库构建(最小件,二期)
③ 现场原型(能用模板按需加载)
④ 部署集成(配置生成 + 字段映射工作台)
   └─ 硬门禁:发客户前人工确认
⑤ 培训沉淀(交付文档包 + 案例归档)
```
- 硬性门禁只在关键质量点;其余流程按项目情况自适应/可跳过
- 每个功能入口:一句话 + 适用场景 + 是否需对抗评审/人工确认(分层:入口简要、详情详细)

## 七、分期实施

| 期 | 内容 |
| -- | ---- |
| **一期(说服力优先)** | ① 案例/交付物层:诊断定稿→可打印 HTML/PDF + 结构化案例存档;② web 项目视图/过程记录;③ monitor 接真实埋点 |
| **二期** | ① 字段映射工作台;② 数据标注与评测集管理;③ prototype 接 core/llm.py 能用模板 |
| **三期** | ① Agent 记忆/案例检索;② 诊断→裁剪接线;③ 知识库分块/质检 |

---

## 八、验收标准

- 一期交付:诊断能一键变成"可打印/可发客户"的交付物;操作台能找到历史项目与过程
- 每个模块自带 manifest,新功能自动入列说明;简介/规范人工维护
- 对抗评审只在关键产出套,质量门禁生效
- 案例/交付物可打印、可发客户、可检索(三期)
