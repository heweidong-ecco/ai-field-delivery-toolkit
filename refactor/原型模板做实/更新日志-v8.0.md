# 原型模板做实 · 更新日志 v8.0

> 日期：2026-08-29
> 版本号：v8.0（从「3/4 模板是壳：只有 qa_agent 真调 core/llm，extract / reasoning / reflexion 走占位返回 finish:已完成任务」升级到「4 个模板全部真调 DeepSeek，现场客户看到的每个模板都是真实 LLM 输出，失败时诚实降级」）
> 关联：基于 v1.2.0 的可注入 llm_call / plan_generator / step_executor / answer_generator 机制与 qa_agent.py 范式（内部 `from core.llm import chat` 真调、返回 `finish:<回答>`）做增量；assembler / API / 前端接口零破坏。
> 本轮主题：④ 原型模板做实。「把三个壳做成真」——信息抽取返回结构化抽取结果、多步推理按计划分步求解、反思型先作答再自检修正；LLM 失败（LLMError）时诚实降级返回错误说明，不装成功。

## 1. 本轮变更

### 核心：三个占位模板真实化（非壳）

`prototype_assembler/templates/` 下 `extract_agent.py` / `reasoning_agent.py` / `reflexion_agent.py` 均注入真实 LLM 调用（仿 `qa_agent.py` 范式，内部 `from core.llm import chat` 真调 DeepSeek）：

1. **extract_agent（ReAct）**：注入 `_extract_llm_call(agent, context, user_input) -> str`，角色「信息抽取助手」，返回 `finish:<结构化抽取结果>`（`实体名 | 类型 | 属性键=属性值`），ReAct 解析 `finish:` 后即为最终答案。
2. **reasoning_agent（Plan-Execute）**：注入 `_reasoning_plan_generator(agent, user_input) -> list[str]`（真调 LLM 生成步骤计划，编号行解析为列表）、`_reasoning_step_executor(agent, context, step) -> str`（真调 LLM 逐步骤执行）、`_reasoning_answer_generator(agent, memory) -> str`（真调 LLM 汇总各步骤中间结果给最终答案）。
3. **reflexion_agent（Reflexion）**：注入 `_reflexion_llm_call(agent, context, user_input) -> str`，角色「先完整作答 → 再简要自检 → 修正后给出最终答案」；反思历史经 `agent._reflection_history` 传给 llm_call，把上一轮评估反馈拼进 system prompt 让模型针对修正。

**诚实降级**：三个模板的 LLM 调用均捕获 `core.llm.LLMError`（及防御性异常），失败时返回明确错误说明（如 `finish: 信息抽取未能完成（LLM 调用失败：…）请检查 DEEPSEEK_API_KEY 配置后重试`），**绝不伪装成成功**。reasoning 的计划生成失败退化为「单步直答」——由 step_executor 用真实 LLM 作答；若后续步骤也失败，最终答案如实暴露。

### 扩展 ReflexionLoop 支持 llm_call 注入（旧接口兼容）

`prototype_assembler/loops/reflexion.py::ReflexionLoop._call_llm` 增加对 `agent.llm_call` 的识别：存在则把反思历史写入 `agent._reflection_history` 并调用，返回值去掉 `finish:` 前缀作为作答结果（供评估器与最终答案使用）；未注入时回退原占位实现（兼容旧行为）。PlanExecuteLoop 原本已支持 `plan_generator` / `step_executor` / `answer_generator` 注入，无需改 loop。

### 诚实标注（前端 / 元信息 / manifest / guide）

- `prototype_assembler/assembler.py` 新增 `TEMPLATE_META`：每个模板的 `label` / `llm`（=「真调 DeepSeek」）/ `rag_ready` / `detail`。
- `core/api.py`：
  - `GET /prototype/templates` 返回 `meta`（旧 `templates` 列表保留，不破坏前端与旧测试）。
  - `POST /prototype/run` 的 `llm_mode` 诚实判定：ReAct/Reflexion 看 `llm_call`，Plan-Execute 看 `plan_generator` / `step_executor` / `answer_generator`；三个模板运行均返回 `llm_mode=llm`。
- 前端（`web/index.html` + `app.js`，零构建）：模板选择下拉用元信息 label 渲染，下拉下方实时显示所选模板「真调 DeepSeek / RAG 就绪」徽标 + 说明；结果区显示模板徽标 + llm_mode。**让客户一眼看出每个模板都是真实 LLM，不再把壳当真。**
- `core/manifest.py` / `core/guide.py` 的 prototype 说明更新为「4 个模板全部真调 DeepSeek」。

### 测试（新 `tests/test_prototype_real.py`，非教学场景）

设备运维 / 工单估算 / 故障说明场景，11 用例（LLM 全部打桩，monkeypatch `core.llm.chat`）：

1. 三个模板 agent 运行产生**真实 LLM 驱动输出**（非占位默认值 `已完成任务` / `任务完成` / `执行结果（反思历史：无）`）。
2. 含**模板角色行为**：信息抽取输出结构化字段（含 `|` 分隔与实体名）；多步推理发生「计划生成 + 步骤执行 + 答案汇总」（≥5 次调用）；反思型第二次调用 system prompt 携带上一轮评估反馈（`未通过质量评估`），最终输出修正后答案。
3. **LLMError 诚实降级**：三个模板各自在 chat 抛 LLMError 时返回错误说明（含 `未配置 DEEPSEEK_API_KEY`），不装成功。
4. **qa_agent 不回归**：`llm_call` 注入 + 打桩 chat 给出非占位输出。
5. API：`/prototype/run` 对三个真调模板返回 `llm_mode=llm`；`/prototype/templates` 返回元信息且旧 `templates` 结构不破坏。
