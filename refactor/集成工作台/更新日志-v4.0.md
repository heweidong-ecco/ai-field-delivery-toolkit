# 字段映射 · 集成工作台 · 更新日志 v4.0

> 日期：2026-08-29
> 版本号：v4.0（字段映射工作台从「映射表格 + LLM 初判 + 导出」升级为「导入真实样例 → 实跑映射 → 校验正确性 → 人工修正迭代 → 导出」的集成工作流）
> 关联：基于既有 mapping/（二期）能力做集成升级；诊断 v2.2 / 数据作战流 v3.0 / 案例 / 项目 / 前端 10 标签均不动。
> 本轮主题：适配器/字段映射占 FDE 现场技术量 60-70%（最大技术痛点）。此前 mapping 只是「表格 + LLM 初判 + 导出适配器」，**不能导入真实样例实跑校验**——映射对不对，现场得自己拿真实数据试才知道。本轮把「真实数据丢进去 → 映射实跑 → 看到每条映射的实跑结果与正确性判断 → 修正 → 再跑，直到达标 → 导出」做成可续接的集成工作流。

---

## 1. 本轮变更

### 核心：导入真实样例 + 实跑校验 + 迭代修正

**现状问题**：映射对不对，只能导出适配器后现场拿真实数据试才知道；LLM 初判可能给错源字段/规则，现场靠猜。

**本轮做成「集成工作台」**（`mapping/service.py` + `core/api.py` + 前端 ⑨ tab）：

1. **导入真实样例数据**（`import_samples`）：`POST /api/v1/mapping/{run_id}/samples` 上传真实源数据 CSV（列名=源字段名）→ 存档案 `samples`（`original_row_count` 原始行数 + `preview` 前 5 行 + `rows` 全量行），供试运行。
2. **试运行 + 实跑校验**（`validate_mapping`）：`POST /api/v1/mapping/{run_id}/validate` 把当前 mappings 对真实样例数据**实跑**——
   - 对每条源数据行，按 mappings 的 rule/expression **真实执行 transform**（`_apply_transform`，语义与 `export_mapping` 生成的 adapter.py 一致：direct/concat/formula/split 可执行；lookup/other 无法自动执行 → 判 fail 并提示「需人工实现」，诚实校验不糊弄）；
   - 生成每个目标字段的映射值（`mapped_output`）；
   - 用「映射校验」LLM（`VALIDATE_SYSTEM`）对每条映射判断 `{target, source_values, mapped_output, verdict: pass/warn/fail, reason}`；
   - 汇总 `{total_rows, mapped_rows, per_field[], counts, success_rate, no_fail_rate}`：`per_field` 每条含 `{target, source, rule, expression, verdict, reason, pass, warn, fail, sampled_rows, examples}`，`examples` 前 5 行（源值 → 映射值 + 执行状态）。
   - 校验结果存档案 `validation`，**可续接**（刷新/重连不丢）。
3. **单行试运行**（`validate_row`）：`POST /api/v1/mapping/{run_id}/validate-row` 对给定一行源数据执行全部映射，返回每个目标字段映射值（前端逐行预览）。
4. **迭代修正**：复用既有 `update_mapping` 修正映射 → 重新 `validate` → 直到达标（`no_fail_rate`/`success_rate` 变化可见）→ 导出。

### 挂项目档案（参考 dataprep）

- `create_mapping` 新增 `project_id` / `customer` 参数：显式 project_id 优先，否则按客户自动建/复用项目（参考 `core/api.py` `_ensure_project`）。
- 创建/调整/校验都会 `add_event` 到项目时间线（事件类型 `mapping`），`ref=run_id`；项目事件携带成功率/无失败率。

### 断点续接

- 结果/样例/校验全部存档案（`tmp/web/mapping/<run_id>/archive.json`），`GET /api/v1/mapping/{run_id}` 返回完整档案。
- 新增 `GET /api/v1/mapping/runs`：列出最近映射任务（名字/状态/映射数/是否已导入样例/是否已校验/成功率/无失败率/项目 id），前端「历史映射 / 继续」。

### API

- `POST /api/v1/mapping/create` — 兼容旧字段，新增可选 `project_id` / `customer`。
- `GET /api/v1/mapping/runs` — 任务列表（断点续接入口）。
- `POST /api/v1/mapping/{run_id}/samples` — 上传真实样例 CSV（`file` + `max_rows`）。
- `POST /api/v1/mapping/{run_id}/validate` — 实跑校验（可选 `max_rows`，默认 20）。
- `POST /api/v1/mapping/{run_id}/validate-row` — 单行试运行。
- `POST /api/v1/mapping/{run_id}/update` / `POST /api/v1/mapping/{run_id}/export` — 复用旧接口，不动。

### 前端（零构建）

⑨ 字段映射 tab 升级为集成工作流：
- 新建表单新增：客户 / 项目 ID / 样例 CSV 文件（可选，创建后自动上传）。
- 工作区三步卡片：① 导入真实样例（文件上传 → 显示行数/列名/前 5 行预览）→ ② 试运行校验（成功率 + 无失败率 + 逐字段 verdict 徽标 + 理由 + 每条映射前 5 行「源值 → 映射值」展开）→ 修正（复用映射表格保存）→ 重跑。
- 「逐行预览」：对前 3 行真实数据逐行跑全部映射，显示每个目标字段映射值。
- 「历史映射 / 继续」：列出历史任务（状态/样例/校验/成功率），点 run_id 恢复完整工作区。
- 校验通过后，映射表格每行「校验」列显示 verdict 徽标。

### 测试

- 新增 `tests/test_mapping_integration.py`（4 用例，**非教学场景**：制造业设备字段映射 + 物流订单字段映射）：
  1. `test_mapping_integration_manufacturing_api`：创建（含错误源字段）→ 导入真实样例 CSV → validate（`device_id` 源字段不存在 → fail，成功率 <100%）→ 修正 → 重跑（`no_fail_rate`/`success_rate` 上升）→ 导出（adapter 语义一致）→ 项目事件 → 断点续接（samples+validation 在档案）。
  2. `test_mapping_integration_logistics_service`：物流订单字段映射，concat `full_address` 真实拼接 → validate 全 pass → validate_row 单行 → 导出 → 项目事件。
  3. `test_mapping_validate_requires_samples`：未导入样例就 validate → 400。
  4. `test_mapping_lookup_rule_fails_honestly`：lookup 规则无法自动实跑 → 校验判 fail 并提示「需人工实现」。
- 校验 LLM 调用全部打桩（`monkeypatch mapping.service._default_json_call`，按 system 是否含「校验」区分初判/校验，不真实调用）；真实链路用 DeepSeek 冒烟单独验证。

## 3. 运行 / 验证方式

```bash
source venv/bin/activate
python -m pytest tests/          # 回归：107 passed（原 103 + 新增 4）

python -m core.main              # 启动服务器，端口 8100
# 浏览器打开 http://localhost:8100 → ⑨ 字段映射
```

跑真实数据（**非教学场景：制造业设备字段映射，真实 DeepSeek**）：
1. ⑨ 字段映射 → 新建映射任务：任务名「制造业设备字段映射」+ 源/目标字段 + 客户「某汽车制造厂」+ 样例 CSV（列：equipment_id,equip_name,temp,pressure,status_code）→ 创建（LLM 初判）+ 自动上传样例。
2. 点「试运行校验」→ 逐字段 verdict：direct 映射大多 PASS；若 LLM 初判 concat 表达式为 `CONCAT(equip_name, ' ', status_code)`（不可执行格式）→ status_note FAIL（提示源字段不存在）。
3. 在映射表把 status_note 表达式改为 `equip_name + status_code` → 「保存人工调整」→ 再「试运行校验」→ status_note 变 WARN/PASS，`no_fail_rate` 升至 100%。
4. 「逐行预览」看每行各目标字段映射值；「导出适配器」得到 adapter.py（`def transform`），与校验语义一致。

## 4. 自测结果

- `pytest tests/`：**107 passed**（v3.0 基线 103，新增 4 个集成工作流用例；旧用例零改动全部保持绿）。
- **真实样例 CSV 跑通 validate/修正/重跑（真实 DeepSeek，非教学场景制造业设备字段映射）**：
  - create（真实 LLM 初判 5 条映射，customer 自动建/复用项目 `project_id=08bc4430`）；
  - upload samples（4 行，列名=源字段名）；
  - validate v1：success_rate **0.8** / no_fail_rate **0.8**，`status_note` **FAIL**（4/4 行执行失败：LLM 初判 concat 表达式 `CONCAT(equip_name, ' ', status_code)` 非可执行格式，源字段不存在）——真实校验抓出了 LLM 初判的格式问题；
  - 修正表达式为 `equip_name + status_code` → save → validate v3：success_rate **0.8** / no_fail_rate **1.0**，`status_note` **WARN**（输出格式符合，源字段缺失无法完全验证拼接），其余 4 条 direct 全 PASS（真实 LLM 理由逐条可读）；
  - **修正后重跑成功率/无失败率变化可见**（fail 1 → warn 1，no_fail_rate 0.8 → 1.0）。
  - export：adapter.py `def transform`，`status_note = str(row.get('equip_name') or '') + str(row.get('status_code') or '')`，与校验语义一致。
- **断点续接**：`GET /mapping/runs` 列出任务（状态/样例/校验/成功率/无失败率）；`GET /mapping/{run_id}` 返回 samples（original_row_count/preview）+ validation 完整档案。

- **validate-row**：单行真实数据跑全部映射，concat 输出「风机R1」正确。
- **前端零构建**：纯 HTML/JS/CSS，`node --check web/app.js` 通过；服务端已确认新表单字段与按钮正常渲染。
