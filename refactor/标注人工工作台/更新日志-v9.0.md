# 标注人工工作台 · 更新日志 v9.0

> 日期：2026-08-29
> 版本号：v9.0（从「服务层是真双人标注、前端是单标注员壳、数据作战流用规则打标」升级到「真实可用的**人工双人标注工作台**」）
> 关联：基于 v1.9.0 的 annotation 服务层（create_annotation_task / add_label / get_task 一致性 stats / build_eval_set 双人一致构建评测集）做增量补齐；只增不改，旧接口/旧字段/旧测试零破坏。
> 本轮主题：③ 数据作战流下挂「人工标注工作台」真实 UI——每个样本两列（标注员 A / 标注员 B）分别存标签、逐行显示一致性、分歧可改判到一致、从数据作战流 cleaned_data 建任务、构建评测集可下载。

## 1. 本轮变更

### 后端：annotation 补齐（只增不改）

`annotation/service.py`：

1. **`list_tasks(limit=50)`**：扫描 `tmp/web/annotation/<run_id>/` 目录，按 `archive.json` mtime 倒序返回 `{run_id, name, total, stats}`，供前端「列出标注任务」与断点续接。
2. **`create_annotation_task_from_dataprep(dataprep_run_id, sample_size=20, name=None)`**：读数据作战流档案 `cleaned_data` 产物取前 N 条 content 作为待标注样本，自动命名 `数据作战流-人工标注-<任务名>`；**样例来源诚实标注**——任务档案新增 `source` 字段 `{type: "dataprep", dataprep_run_id, dataprep_name, sample_size}`（只增字段，不破坏既有任务）。cleaned_data 缺失/不存在 → 诚实报 ValueError/FileNotFoundError。
3. **`get_task` 增加每样本一致性明细**：每个 item 新增 `consistency` 字段（`unlabeled` 未标 / `only_a` 仅A / `only_b` 仅B / `only_one` 仅一人非A/B / `agreed` 一致 / `disagreed` 分歧），stats 计数改用同一判定函数（空字符串标签视为未标），供前端逐条显示。旧字段 stats / items / labels 不变。

`core/api.py`（新增端点，旧端点不动）：

- `GET /annotation/runs` → `list_tasks`（注册在 `GET /annotation/{run_id}` **之前**，避免路由遮蔽）。
- `POST /annotation/from-dataprep` → `create_annotation_task_from_dataprep`。

### 前端：③ 数据作战流下挂「人工标注工作台」真实 UI（零构建）

- **从数据作战流建任务**：下拉列已完成清洗的数据作战流 run（`/api/v1/dataprep/runs`，仅列有 cleaned_data 产物的）+ 样本数 → 调 `from-dataprep` 建任务；保留手动粘贴样本建任务（两条路径都进新工作台）。
- **双人标注工作台**（新 `renderAnnWorkbench`，独立于旧 `renderAnnTask`）：每样本两列输入（标注员 A / 标注员 B，可分别存），逐行一致性徽标（未标/仅A/仅B/一致✅/分歧⚠️）；顶部实时一致性统计（一致 N / 分歧 M / 未标 K / 共 T）。
- **分歧处理**：分歧样本单独列出一节（两标注员标签对照），在下方工作台给任一标注员改标签后「保存标注」重算一致性，直到一致。
- **构建评测集**：调 `build-eval`，显示一致/分歧条数，一致样本生成评测集（`/artifacts/annotation/<run_id>/eval_set.json` 可下载）。
- **任务列表**：「列出标注任务」→ `GET /annotation/runs`，可打开历史任务进工作台续做。
- **数据作战流衔接与诚实标注**：数据作战流 `annotate` 步骤产出的 `annotation_eval_set` 产物面板标 **「规则自动打标」**（流水线便利，保留）；产物旁新增「去人工标注工作台精标」按钮（带该 run 的样本源）→ 建 from-dataprep 任务进工作台。人工工作台标题/说明明示「人工标注」。
- 旧 `renderAnnTask`（单标注员）函数体**原样保留**（兼容，不删），但面板统一路由到新双人工作台。

### 测试（新 `tests/test_annotation_workbench.py`，非教学场景）

制造业传感器 CSV 真实数据场景，7 用例（隔离 ANN_ROOT / dataprep ARCHIVE_ROOT 到 tmp，语义去重打桩固定哈希向量，不联网）：

1. `from_dataprep` 建任务：样本来自**真实 cleaned_data**（非空），内容一致，source 诚实标注；不存在 run / 无 cleaned_data 诚实报错。
2. 双人标注 A/B → `get_task` 一致性 stats 正确（一致/分歧/未标计数）且每样本 consistency 明细正确。
3. 分歧样本检出 → 改 B 标签后一致 → `build_eval_set` 只含一致样本、分歧被列出/清空。
4. `list_tasks`：按 mtime 倒序，字段齐全。
5. API 全链路（TestClient）：`from-dataprep` → `label`（双人）→ `get`（stats + consistency）→ `build-eval`（分歧列出、一致进评测集、改判后再 build 只含一致）→ 评测集产物落盘 → `runs` 列表。
6. 旧端点不破坏：手动 `create` / `label` / `get` / `build-eval` 全通，非 A/B 标注员也给出合理 consistency。

```bash
# 「人工标注工作台」：从数据作战流建任务（下拉选 run + 样本数）→ 每样本两列（标注员 A/B）分别存
```

