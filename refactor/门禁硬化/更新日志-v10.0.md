# 门禁硬化 · 更新日志 v10.0

> 日期：2026-08-29
> 版本号：v10.0（从「质量门禁只是状态展示」升级到「**关键质量点真阻断** + 诚实的人工强制继续通道」）
> 关联：基于 v7.0 的 `core/workflow.py`（5 步骨架 + gate_passed）与既有端点（/diagnosis/finalize 已强制 confirmed）做增量硬化；只增不改，旧接口/旧字段/旧测试零破坏。
> 本轮主题：`gate_check(stage_key, project_id)` 统一门禁判定（诊断须人工确认 / 数据须真实质量评估 / 文档包须人工确认）；`/prototype/run` 数据门禁 403 真阻断（force 强制通道诚实记录 gate_override）；`/cropper/from-diagnosis` 未确认 400；`/cases/create-doc-package` 文档包确认门禁 400；前端（④ 原型 / ⑧ 项目文档包 / warroom 工作流）诚实展示门禁 reason 并做人工勾选。

---

## 1. 本轮变更

### A. 门禁判定（核心，`core/workflow.py`）

1. **新增 `gate_check(stage_key, project_id=None) -> dict {allowed, reason, evidence, stage, mode}`**：只做判定、不负责拦截，全部基于真实档案（非写死）：
   - `diagnosis`：允许 = 该项目有已确认诊断（项目 diagnosis 事件，或诊断 run 档案 `project_id==pid 且 confirmed`）；否则 reason「发客户前必须人工确认」。
   - `data_prep`：允许 = 该项目有 dataprep run（`project_id==pid`）**且其 `quality_report` 产物文件真实存在**（数据被真实评估过＝达标）；否则 reason「数据未达标不进原型（缺少质量评估）」。
   - `deliver`：允许 = 该项目有已确认诊断 **且** 存在带 project_id 的 doc_package 案例；否则 reason「文档包需人工确认」。
   - `project_id` 为空：用全局判定（全局有已确认诊断 / 全局有 quality_report 产物），reason 注明「（全局判定）」。
2. **`project_status` 的 `gate_passed` 复用/对齐 gate_check**（只增不破坏）：诊断/data_prep/deliver 三步的 `gate_passed` 改由 `gate_check` 判定，并**新增 `gate_reason` 字段**（只增字段，旧字段不动）；无门禁步骤（prototype/deploy）`gate_passed` 仍为 None。既有 v7.0 `done/evidence` 判定逻辑原样保留。

### B. 真阻断（硬门禁，`core/api.py`）

1. **`POST /prototype/run`**：`PrototypeRunRequest` 增可选 `project_id: str = ""` 与 `force: bool = False`（只增字段）。传 `project_id` 时先 `gate_check("data_prep", project_id)`：
   - 未通过且非 force → **HTTPException 403**，`detail` 为 `{message, gate_reason, stage}`（含 gate_reason，前端可读）。
   - force=true 通过时响应**附加 `gate_override: true + gate_reason`** 诚实记录（前端要求人工勾选强制）。
   - 未传 `project_id` → 不拦，响应附 `gate: {checked: false}`（旧调用行为不变）。
   - 响应统一附 `gate: {checked, allowed, reason}`（传入 project_id 时）。
2. **`GET /cropper/from-diagnosis/{run_id}`**：先查该诊断 run `confirmed`；未确认 → **HTTPException 400**，detail「诊断未定稿确认,禁止据此裁剪发客户」。
3. **`POST /cases/create-doc-package`**：`DocPackageRequest` 增 `confirmed: bool = False`。要求 `confirmed=true` **或** 该项目已有已确认诊断，否则 → 400 带 reason「文档包需人工确认」；响应附加 `gate` 结果（checked / allowed / reason / evidence / confirmation，诚实记录确认来源：request_confirmed 或 confirmed_diagnosis）。生成的文档包会落盘 `project_id`（供后续 deliver 门禁判定）。
4. **`POST /diagnosis/finalize`**：已强制 `confirmed=True`（既有，保留不破坏）。
5. 新增 **`GET /workflow/gate?stage=&project_id=`**：返回 `gate_check` 结果，供前端运行前展示「数据达标 / 文档包确认」门禁状态（注册在 `/workflow/{project_id}` 之前避免路由遮蔽）。

### C. 前端（`web/index.html + app.js`，零构建，诚实）

- ④ 原型 tab：运行表单加可选 `project_id` 输入；输入后实时查 `/workflow/gate?stage=data_prep` 显示「数据达标门禁」状态（通过/未过 + reason）；未过时**禁用运行按钮**并显示 reason + 「强制继续」checkbox（勾选后才可运行）；运行响应渲染 `llm_mode` / `gate.checked` / `gate_override` 徽标 / `sources`（既有行为保留）。
- ⑧ 项目页文档包按钮：点击弹「确认已人工定稿 / 发客户前确认」checkbox，**未勾选不发请求**；成功显示确认提示（confirmed=true）+ 文档包链接。
- warroom 工作流：门禁未过的步骤加明显「门禁未过：\<reason\>」提示（只展示 `gate_check` 的 reason，不造假）。
- `api()` 错误解包升级：后端 403 `detail` 为 `{message, gate_reason}` 对象时解包为可读字符串（对旧字符串 detail 兼容）。

### D. 测试（新 `tests/test_gates.py`，非教学场景）

15 用例，覆盖：无达标数据的项目跑原型 → 403 + gate_reason；建好 dataprep run（质量产物在）的项目 → 200 + gate.allowed；force → 200 + gate_override；未传 project_id → 不拦 + checked:false；未确认诊断 from-diagnosis → 400；已确认 → 200；文档包无确认 → 400、有确认或项目已确认诊断 → 200（含只传 run_id 自动带出 project_id）；finalize 强制 confirmed 回归；gate_check 服务层判定（真实档案）与全局判定；`/workflow/gate` 端点。LLM 全打桩、语义去重打桩（固定哈希向量不联网）、诊断/dataprep/cases/projects 档案根目录隔离到 tmp。

```bash
# 未过 → 运行按钮禁用 + 强制继续 checkbox；⑧ 项目页「生成项目文档包」→ 先勾选人工确认
# warroom 工作流：门禁未过步骤显示「门禁未过：<reason>」
```

curl 验证（关键接口）：

```bash
# 1) 无达标数据的项目跑原型 → 403 + gate_reason
# <PID> 为一个没有数据作战流任务（或 quality_report 产物缺失）的项目
curl -X POST localhost:8100/api/v1/prototype/run -H 'Content-Type: application/json' \
  -d '{"template":"knowledge_qa","user_input":"什么是RAG？","project_id":"<PID>"}'
# 403 {"detail":{"message":"数据未达标不进原型（缺少质量评估）","gate_reason":"数据未达标不进原型（缺少质量评估）","stage":"data_prep"}}

# 2) force=true → 200 + gate_override
curl -X POST localhost:8100/api/v1/prototype/run -H 'Content-Type: application/json' \
  -d '{"template":"knowledge_qa","user_input":"什么是RAG？","project_id":"<PID>","force":true}'
# 200 {"gate_override":true,"gate_reason":"数据未达标…","gate":{"checked":true,"allowed":false,"reason":"数据未达标…"}}

# 3) 未传 project_id → 不拦 + gate.checked=false
curl -X POST localhost:8100/api/v1/prototype/run -H 'Content-Type: application/json' \
  -d '{"template":"knowledge_qa","user_input":"什么是RAG？"}'
# 200 {"gate":{"checked":false}}

# 4) 未确认诊断裁剪 → 400
# <RUN> 为一个未 finalize（confirmed=false）的诊断 run
curl localhost:8100/api/v1/cropper/from-diagnosis/<RUN>
# 400 {"detail":"诊断未定稿确认,禁止据此裁剪发客户"}

# 5) 文档包无确认 → 400；confirmed=true 或项目已确认诊断 → 200
curl -X POST localhost:8100/api/v1/cases/create-doc-package -H 'Content-Type: application/json' \
  -d '{"run_id":null,"project_id":"<PID>","sections":["架构说明"]}'
# 400 {"detail":"文档包需人工确认"}
curl -X POST localhost:8100/api/v1/cases/create-doc-package -H 'Content-Type: application/json' \
  -d '{"run_id":null,"project_id":"<PID>","sections":["架构说明"],"confirmed":true}'
# 200 {"gate":{"checked":true,"allowed":true,"confirmation":"request_confirmed",...}}

# 6) 前端门禁状态端点
curl "localhost:8100/api/v1/workflow/gate?stage=data_prep&project_id=<PID>"
# {"allowed":false,"reason":"数据未达标不进原型（缺少质量评估）","evidence":[],"stage":"data_prep","mode":"project"}
```

## 4. 自测结果

- `pytest tests/`：**161 passed**（v9.0 基线 146，新增 15 个 test_gates 用例；旧用例零改动全部保持绿）。
- **门禁判定真实（非写死）**：`gate_check` 全部基于真实档案——data_prep 检查 dataprep run 的 `products.quality_report.exists`；diagnosis 检查诊断 run 档案 `confirmed` + project_id；deliver 检查已确认诊断 + 带 project_id 的 doc_package 案例。测试用真实数据作战流（传感器 CSV → 清洗 → 质量报告产物）验证。
- **原型数据门禁真阻断**：无达标数据项目 `/prototype/run` 返回 403，detail 含 gate_reason；有 quality_report 产物的项目 200；force=true 200 且 `gate_override:true + gate_reason` 诚实记录；未传 project_id 不拦且 `gate.checked:false`（curl 冒烟 + 自动化测试）。
- **裁剪/文档包确认门禁真阻断**：未确认诊断 `/cropper/from-diagnosis` 400；已确认 200。文档包无确认 400、confirmed=true 或项目已确认诊断 200（confirmation 诚实区分 request_confirmed / confirmed_diagnosis）；只传 run_id 自动带出 project_id。
- **强制继续通道诚实**：force 仅在前端人工勾选时发出（未勾选前端直接阻止请求）；后端 403 仍兜底；通过时响应附 `gate_override:true + gate_reason`。
- **既有能力不破坏**：`PrototypeRunRequest`/`DocPackageRequest` 只增字段，旧调用不传新字段行为不变；`/diagnosis/finalize` 强制 confirmed 保留；`project_status` 旧字段不动（只增 gate_reason）；`pytest tests/` 全绿证明旧 146 用例零改动。
- **前端零构建**：`node --check web/app.js` 通过；④ 原型门禁展示/强制 checkbox/override 徽标、⑧ 文档包确认流程、warroom「门禁未过：reason」代码完备；真实浏览器可用性由总工程师（独立身份）核验。
