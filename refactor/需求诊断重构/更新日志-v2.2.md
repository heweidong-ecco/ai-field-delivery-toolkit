## 1. 本轮变更

### 核心：报告新增第 14 章「商务提案（供洽谈讨论）」

现状问题：诊断报告已能回答「技术上能不能做、值不值得投」，但甲方决策最缺「投多少、什么时候看到东西、我（甲方）要出什么、不满意怎么退出、不做损失多大」这一页。本轮补齐。

五块内容（全部为实质内容，非一两句）：
1. **投入估算与分期**（`investment_estimate`）：按「试点期 / 一期 / 二期」分档，每档给做什么（focus）、范围（scope）、投入区间（万元，investment_range）、投入依据（basis，引诊断的集成复杂度/数据准备量/组织培训量等）、交付物（deliverables）；全局 `total_range` 总投入区间；`disclaimer` 明确标注「**此为讨论用初步估算，最终以商务洽谈确认为准**」。
2. **时间里程碑**（`milestones`）：分阶段时间线（试点 2 周出原型 → 一期 X 周 → 二期 X 周），每项给阶段/时长/**「何时看到第一个能用的东西」（first_usable，具体到第几周看到什么）**/阶段里程碑/开工前提。
3. **责任清单**（`client_responsibilities` + `vendor_responsibilities`）：甲方责任具体到条目（数据/接口/人员/决策），每条含类别、须在何时提供、甲方责任方、依据（引约束/假设/集成需求）、是否**阻塞开工**（blocking）；乙方责任并列，摊开责任边界。
4. **试点范围与退出机制**（`pilot_and_exit`）：试点范围（具体到单场景/单类样本/设备数）、**可量化成功标准**（≥3 条，带数字如准确率≥80%）、失败/不满意退出条件（可触发可判断）、联合评审时点、退出善后。
5. **替代方案与不做的代价**（`alternatives_and_cost`）：≥2 个替代方案对比（现有系统规则改造 / 人工流程优化 vs 引入 AI），每项含优缺点/投入区间/风险/结论；`cost_of_inaction` 明确写「不做」的机会成本（带数字）；`recommendation` 倾向建议。

### 实现方式

- **新增一个商务评估 LLM 调用**（`diagnosis/agents.py`）：`COMMERCIAL_PROPOSAL_SYSTEM`（「AI 项目交付商务评估」角色）+ `run_commercial_proposal(diagnosis_context)`；输入诊断上下文（技术 5 维 `dimension_scores` + 非技术可行性 `non_tech_feasibility` + 范围/功能需求/数据要求/风险/假设/分阶段建议/需求原文），输出上述 5 块结构化 JSON；`_normalize_commercial_proposal` 兜底补默认结构。
- **编排层接入**（`diagnosis/orchestrator.py`）：
  - 新增 `commercial_proposal(run_id)` 独立函数（可单独调用预演）；
  - `finalize` 定稿时自动调用 `_draft_commercial_proposal`（LLM，失败用 `_fallback_commercial_proposal` 规则兜底，**不阻断定稿**），写入档案 `business_proposal` 并进 `report.business_proposal`；
  - `_build_report` 报告新增 `business_proposal` 字段；多轮版本每次定稿都基于最新诊断输出重新起草。
- **渲染**（`cases/render.py`）：新增 `_chapter_business_proposal`（第 14 章），插入「13 验收标准」之后、「附录 A」之前；附录 A/B 顺延为第 15/16 章（TOC 与章节号同步）；前端零构建，打开报告即可见。

### 兼容性

- 既有能力零破坏：5 维打分/置信度/分歧/多轮累积/打开按钮/对抗内联/非技术可行性/附录全文均未动；报告为纯 HTML，前端无需改交互。
- 商务提案 LLM 失败自动降级为规则兜底，`finalize` 永不因商务提案失败而中断；旧接口（start/review/finalize/next-version/feedback/cases/create）签名不变。
- 预算：`finalize` 新增 1 次 LLM 调用，单次诊断仍 ≤ 9 次（v1 定稿 = start 2 + review 1 + finalize 1 = 4；完整两轮 = 9）。

## 3. 运行 / 验证方式

```bash
source venv/bin/activate
python -m pytest tests/          # 回归：99 通过（原 98 + 新增 1 个 v2.2 渲染用例）

python -m core.main              # 启动服务器，端口 8100
# 浏览器打开 http://localhost:8100  → ① 需求诊断
```

跑真实诊断（**本轮自测场景：制造业预测性维护**，不再用 AI助教/教学场景）：
1. 输入需求：「为客户汽车制造工厂搭建基于设备传感数据的预测性维护系统，降低非计划停机，覆盖200台关键设备，数据来自MES与SCADA系统」→ 开始诊断。
2. 人工打分 + Reviewer 评审 → 确认定稿 → 打开报告。
3. 报告第 14 章「商务提案（供洽谈讨论）」：14.1 投入估算与分期（试点/一期/二期，区间+依据+洽谈口径）→ 14.2 时间里程碑（试点 2 周出原型等）→ 14.3 责任清单（甲方阻塞开工条目 + 乙方责任）→ 14.4 试点范围与退出机制（可量化成功标准 + 退出条件）→ 14.5 替代方案与不做的代价；附录 A/B 顺延为 15/16。
4. 客户反馈 → 生成下一版 → 再定稿 → 商务提案基于最新诊断输出重新起草并随版本累积。
