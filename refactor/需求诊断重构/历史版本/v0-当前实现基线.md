# v0 · 重构前实现基线

> 重构前「需求诊断」模块的现状快照,供对比回溯。日期:2026-08-29。重构起点即此版本。

## 现状:单次 LLM 打分 + 人工复核 + 简单报告

**用户判定:单次打分无价值,不如 DeepSeek 网页对话——因此发起重构(见 `../重构方案-v1.0.md`)。**

### 涉及文件

| 文件 | 作用 |
| ---- | ---- |
| `diagnosis/ai_scorer.py` | 单次 LLM 中立评估:默认中立提示词 + DeepSeek 调用 + JSON 解析 + 关键词规则兜底 + `ai_evaluate()` |
| `diagnosis/checklist.py` | `AIFeasibilityChecklist`:五维(生成性/推理复杂度/不确定性容忍度/数据可得性/实时性要求)各 1-5,求和 5-25,阈值 20/15/10 切四档 |
| `diagnosis/report.py` | `DiagnosisReportGenerator`:`generate()`(v1.0)+ `generate_with_review()`(v2.0,含人工复核)+ `save_report()` |
| `core/api.py` | 端点:`POST /diagnosis/evaluate`(手动打分)、`POST /diagnosis/ai`(单次 LLM)、`GET /diagnosis/default-prompt`、`POST /diagnosis/report`(支持 `manual_review`) |
| `web/index.html` + `web/app.js` | 诊断页:需求文本 + 可自定义提示词 + AI 诊断 → 人工复核打分 → 生成报告(5 部分渲染) |

### 关键实现

- **单次调用**:`ai_scorer.ai_evaluate` 一次 `chat.completions.create`(temperature 0.2)产出五维打分 + 理由 + 总结;JSON 正则解析;失败降级到关键词规则(`llm_mode: "rule-fallback"`)。
- **中立提示词**:`DEFAULT_NEUTRAL_PROMPT` 要求严格中立、只依据需求文本、JSON 输出;前端可编辑,`prompt_modified` 未实现(无标注)。
- **人工复核**:AI 结果预填人工打分面板 → `generate_with_review` 合并 AI + 人工,含 `score_comparison`(delta)、`final_conclusion`(以人工打分为准)、`recommendations`(含分歧 ≥2 提示)。
- **无多 Agent、无循环、无版本、无客户反馈、无置信度、无预算控制、无持久化档案**(结果不落盘,靠前端展示)。

### 已知缺陷(重构要解决的)

1. 单次 LLM 打分,无对抗评审 → 自证幻觉风险
2. 无"AI 再评分人工"环节 → 复核循环缺失
3. 无剖析提问轮 → "人脑 10 倍信息"未被挖掘
4. 无版本循环 / 客户反馈 → 不匹配真实交付链路
5. 打分阈值未校准、分数被当作权威
6. 兜底规则输出与 AI 结论外观相似,易误读
7. 提示词可改但报告不标注"已修改"
8. 无置信度、无预算、无档案
