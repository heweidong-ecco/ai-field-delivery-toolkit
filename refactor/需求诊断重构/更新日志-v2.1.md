## 1. 本轮两个改进

### 改进一：对抗评审过程内联进正文（`cases/render.py`）

现状问题：对抗/盲审/评审只在附录 A 以 JSON 呈现，外行看不懂；正文只有 Generator 单方结论。

改动：
- **每个维度的分析块**（第 6 章五维可行性深度分析）内新增「对抗评审过程」内联可读块，全部为提炼后的通顺中文、禁止贴 JSON/代码：
  - Generator 立场与论证（提炼为中文，含得分）
  - Critic 独立盲审立场（提炼为中文，含得分）+ 与 Generator 的分歧点（引需求原文 evidence）
  - Reviewer 对人工分的评审意见（同意 / 修正为 X 分 + 论证）
  - 采纳结论：取谁的（Reviewer 修正 / 双方一致 / 分歧留待客户决策）
- **关键结论处**（第 1 章执行摘要 + 第 7 章整体可行性评估）新增简短内联「对抗评审速览」：谁同意、谁分歧、Reviewer 是否修正、非技术层面哪些维度存在信号分歧。
- **附录 A 完整原文保留不删**（证据保留，含 v2.1 新增的非技术字段），正文呈现「提炼后的过程」。

### 改进二：可行性评估从 5 维技术扩展为全景（`diagnosis/agents.py` + 报告）

现状问题：5 维只覆盖技术可行性，甲方认为片面。

改动：
- **保留 5 维作为「技术可行性」**：打分体系、置信度、分歧计算不变（`dimension_scores` / `dimension_analysis` / `compute_confidence` / `_score_divergences` 均未动）。
- **Generator 新增 `non_tech_feasibility`**（非技术可行性，定性），五项，每项含 `{item 评估, basis 依据, signal 红/黄/绿, advice 建议}`：
  - `business_value` 商业价值与 ROI（投入产出、价值主张、回报周期）
  - `organization` 组织承接与变革阻力（客户组织是否接得住、决策链、培训、用户接受度）
  - `integration` 系统集成复杂度（对接系统、字段映射/适配器、权限——FDE 参考中占 60-70% 技术量）
  - `compliance` 合规与安全（数据隐私、监管、数据驻留）
  - `risk_overview` 风险全景（汇总各维风险 + 缓解 + 责任方）
  - 额外 `overall_recommendation` 综合建议（worth_investing 值不值得投 / budget_scale 投多少 / main_resistance 主要阻力 / first_steps 先做什么）
- **Critic 新增 `non_tech_audit`**（独立盲审非技术可行性）：同样五项，每项独立评估 `{item, basis, signal, advice, audit_note}`（audit_note 为独立担忧/分歧点），外加 `overall_audit_note` 对整体投入建议的独立判断。
- **报告新增第 7 章「整体可行性评估」**：
  - 7.1 技术可行性：五维得分概览（Generator / Critic 盲审 / 人工 / Reviewer 修正 / 采纳分）
  - 7.2 非技术可行性：每维 Generator 立场 vs Critic 盲审（内联对抗 + 红黄绿徽章 + 依据 + 建议 + 分歧判定）
  - 7.3 综合建议：值不值得投、投多少、主要阻力、先做什么 + Critic 盲审整体判断
- **兼容**：`_normalize_non_tech_gen` / `_normalize_non_tech_crit` 为缺失单项补默认结构；`next_version` merge 字段清单新增 `non_tech_feasibility` / `non_tech_audit`，多轮累积不丢；旧字段（`dimension_scores` / `reasons` / `verdicts` / `bias`）与旧接口/测试不受破坏。

## 3. 运行 / 验证方式

```bash
source venv/bin/activate
python -m pytest tests/          # 回归：98 通过（原 97 + 新增 1 个 v2.1 渲染用例）

python -m core.main              # 启动服务器，端口 8100
# 浏览器打开 http://localhost:8100  → ① 需求诊断
```

跑真实诊断（AI助教场景）：
1. 输入需求（高校在线教育平台「AI 助教」）→ 开始诊断 → 前端展示 Generator/Critic 完整对抗过程（含非技术可行性/非技术盲审）。
2. 人工打分 + Reviewer 评审 → 确认定稿 → 前端出现「打开报告（HTML/PDF）」按钮。
3. 打开报告：第 6 章每个维度下有「对抗评审过程」可读块；第 7 章「整体可行性评估」含技术 5 维 + 非技术各维（Generator vs Critic 内联对抗）+ 综合建议；执行摘要含「对抗评审速览」；附录 A 完整原文保留。
4. 客户反馈 → 生成下一版 → 再定稿 → 非技术字段随版本累积保留。
